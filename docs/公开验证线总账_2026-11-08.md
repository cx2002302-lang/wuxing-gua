## 二、三条主线

### 主线一：口径线——从「等变二义性」到三级显式声明，再到逐元素同态律

1. **外部复核的致命发现（2026-10-29）**：同一群、同一数据，两种同样合理的动作名解释会给出相反判决（默认口径 pass / 严格口径 reject，TV 1.0）。手算验证确认这是数学事实而非代码 bug——开关类系统（动作绑状态位）该换名，事件类系统（动作是外部事件）不该换名，而工具只有一套隐含口径。
2. **三级声明（波 33）**：口径从「判据去猜」升级为「模型作者声明」——群文件可选 `semantics` 块；check 按声明四分派（bitstring / generalized / strict / explicit），判据数学零改动；未声明群按 relabel 判读但盖 `semantics_assumed=true` 戳记并在 stderr 显著警示。三真实案例属开关类，其结论在显式声明口径下**成立、不翻案**；rung 1c 样例给出同一群两口径对照的可复现实证（fixed → reject / relabel → pass）。
3. **explicit 缺陷（波 36）与修复（波 37）**：mini2048 入卷使 explicit 口径有了真实系统样本，却暴露出单全局 `action_map` 在数学上容纳不了任何非平凡动作改名群（恒等元强制 ρ=id）。修复=逐元素映射表 `action_maps` + 整表群同态律校验；判据 TV 机制逐字保留，mini2048 三群翻案为 pass、两个应拒对照维持 reject。
4. **fail-closed 同态律修复（并行工作线，在途见 §七）**：对 >500 元素的同态律全检从「抽样」改为「超限一律干净拒答」（`HOMOM_FULL_CAP=500`）；修复前抽样路径的历史读数 512 注入有 **161 个（31.4%）漏检**在案为证据；修复后双分支变异测试：>500 规模 **512/512** 注入全拒、≤500 规模 **256/256** 注入全被「同态律违反」抓住（证明全检真的在跑而非闸门焊死）。该修复本总账落盘时点**未提交**，其结论以该线自带验收为准。

### 主线二：法庭线——symmetry-court 的四能力闭环

- **案卷**：12 个公开标准案卷（tcp/dhcp/imap ← RFC 9293/2131/3501；raft-etcd/k8s/hadoop/tls13/usb2 ← 五个真实外部系统盲测转录收编；mini2048/lightsout3/sliding2x3/hanoi3 ← 四个非平凡正控）。每边逐条引用一手来源。
